# 代理、故障切换与流终态

修改代理重试、冷却、取消、SSE 或 Responses WebSocket 时读取相关章节。路径相对仓库根目录；省略目录的 app 文件位于 `internal/app/`。

## 动态思考等级

- Responses input 中的 `compaction_trigger` 与 `/responses/compact` 一样不调用动态思考判断、不推进业务轮状态。跨协议压缩摘要成功后，HTTP/WS 执行会话用 ccLoad 摘要条目替换旧 input；通过 `previous_response_id` 续聊只回放摘要与新输入，不能再回放旧 trigger。摘要计费复用真实上游 usage，摘要生成失败或截断不提交成功压缩结果。

- 等级作用于业务模型，与协议无关：OpenAI Chat、Responses（HTTP/WS）、Anthropic Messages、Gemini generateContent/streamGenerateContent 入口都参与，仅生成端点本身是业务轮；`/responses/compact`、`/responses/input_tokens`、`count_tokens`、`:countTokens` 等子资源不调用判断模型也不推进状态。等级按实际模型目录档位钳制后，像思考后缀一样写入客户端协议请求体（Chat `reasoning_effort`、Responses `reasoning.effort`、Anthropic `output_config.effort`（`thinking.type=enabled` 改为 adaptive）、Gemini `thinkingLevel`），由协议转换带到任意上游；发送边界按实际 wire 等级与判断结果逐字比较判定是否生效（`max` 与 `xhigh` 是不同档位，不视为同级）。任意协议 user 消息中以 `<system-reminder>` 开头的内容块计入指令而非任务，Claude Code 本地命令块（`<local-command-caveat>`/`<local-command-stdout>`/`<local-command-stderr>` 及无参数的 `<command-name>`）既非任务也非指令，直接从判断上下文剔除；只含提醒或本地命令块的 user 消息不算本轮输入；Anthropic 投影跳过 thinking 块，无 `thinking` 字段时与后缀一致写为 adaptive（转换器只在 adaptive 下读取 `output_config.effort`）；Claude Code 会话身份取 `X-Claude-Code-Session-Id`，缺失时取 `metadata.user_id`。客户端是否指定非 `auto` 思考后缀在历史继承和自动注入之前记录；仅该后缀豁免判断，请求体中的显式等级可由判断结果覆盖。同一轮只执行一次判断，Key/URL/协议/渠道重试与 WS 完整回放、原生增量发送共用结果；目标模型能力不明确时跳过注入。
- 判断读取可获得的完整会话，最多 24 KiB 文本且保持 UTF-8 边界。无可靠会话 ID 时仅做独立请求判断；有身份时按认证主体、协议、会话/线程及业务模型隔离，状态不落数据库。状态最多保留 1024 个身份，按执行会话 TTL 清理；满时新身份独立判断，已有身份继续复用。升级立即生效，降级需连续两次有效低等级建议；判断 state 只发 `conversation`，不发当前生效等级（回放显示它把判断锚向现等级、只会阻碍降档，迟滞由降级确认负责）；工具续轮每三轮重评，失败或新约束提前重评（结构化错误/退出码优先，否则只看输出首行标记）；与工具结果同条消息的真实用户文本（Claude Code 合并工具执行期间的输入）按用户输入立即重评，客户端注入的提醒与本地命令不算。上下文不完整、错误与取消不会推进降级；超 24 KiB 截断（保留原始任务、最新要求、指令摘要和仅含对话的尾部，指令不在尾部重复）的建议仍计入降级确认；判断模型给出的 confidence 低于 0.3 时按 `low_confidence` fallback：记录建议与置信度但不改变已生效等级（首轮即保留客户端等级），下一轮强制重判；指令摘要覆盖顶层 instructions、system/developer 消息和 Codex AGENTS/user_instructions，多个来源共享独立预算。上下文不完整只有三种：请求结构损坏（JSON 无效、未知 role、content 形状错误）；仍带 `previous_response_id`（WS 与本进程 HTTP 续接已先用内存历史补全，剩下的说明历史只在上游）；最新一段输入（最后一个模型产出之后，含工具结果的数组或字符串化内容）带图片/文件，复用轮也须检查。历史中的媒体和未知 item/block/part 类型都投影为 `[类型]` 占位符，照常判断，以免整段会话被一张旧截图或一个新类型永久作废。Codex 的 `additional_tools`、`configuration_update` item 不是会话内容，投影与“本轮是否为用户输入”判断均跳过；多代理 v2 的 `agent_message`（派发任务、代理间消息与最终回报）是会话内容，加密的 `encrypted_content` 部分投影为 `[encrypted]`。子代理线程的 user 消息只有注入上下文，没有真实用户任务时，以父代理的 NEW_TASK 及同一发送方后续消息作为截断摘要中的原始任务与最新要求；主线程只收到发给自己的回报，不受影响。子代理与主线程共用 `Session-Id`，状态按 `Thread-Id` 隔离。Codex `generate:false` 预热请求没有可判断的输入，直接记 `skipped/prewarm`：不调用判断模型、按客户端等级发送、不改动会话状态与待确认降级。Codex guardian 审批子代理（请求头 `X-OpenAI-Subagent: guardian`）审查的是另一代理的计划动作，判断模型会按被审任务定级，同样记 `skipped/guardian` 并按客户端等级发送。投影中的 Fernet 密文（`gAAAAA…`，Codex agent 消息与 reasoning 密文，含 JSON 参数和 code-mode 源码）统一替换为 `[encrypted]`；Anthropic thinking 签名与 Gemini thoughtSignature 本就不进投影。状态在业务发送边界按实际 wire 等级提交，提交后版本递增，同轮后续重试不能撤销。判断候选等级取业务模型（请求原始模型）在 `models.json` 全部目录（含 Lookup 不读的 kimi/xai/meta/gemini-cli）中档位最全的 `Thinking.Levels` 里有 criteria 的档位（`low`…`max`），不足两档用 `low`–`xhigh`；发送钳制优先上游协议对应目录，无档位再用同一全目录兜底；只有预算没有档位的模型（gemini-2.5、Claude 4.5 及更早）仍跳过注入；判断结果不在候选内视为 `invalid_response`。criteria 必须按等级升序输出 JSON（不能用 Go map 的字母序：回放中加入 `max` 后字母序把多条中档样本推到 high）。判断 instructions 与 criteria 经真实回放 A/B 选定（更细的 criteria 会拉低中档置信度并把长审查推到 xhigh，state 加 phase/has_tools 无净收益；`max` 用“Research-grade…”措辞，普通样本与四档基线一致，含糊的“最难问题”措辞会让 xhigh/max 低置信度摇摆），修改须先用 docs 样本回放对比。
- 整个判断过程（包括失败后的冷却写入）共用一个超时预算；预算耗尽允许冷却写入失败，不能延迟业务回退。容量满直接回退，不递归判断、不执行客户端工具、不跨渠道重试。失败保留先前有效等级，无有效等级则使用原请求默认行为；在实际业务发送前取消不提交新状态。较旧的并发 HTTP 判断不能覆盖较新的状态。

## Responses WebSocket 会话与资源

- **HTTP 跨协议续接**：流式 HTTP Responses 有执行会话身份且本进程持有 `previous_response_id` 对应历史时，跨协议转换使用完整输入、上一轮输出及工具调用历史；原生 HTTP 保持客户端请求体。转换后的终态保存客户端实际收到的 Response ID 和 output。历史不可用时拒绝该跨协议候选并保留原生候选回退机会；无可用候选则返回 400，要求发送完整 input 并移除 `previous_response_id`。`response.incomplete` 与 completed/done 同属转换流终态，不等待上游断开连接。
- **执行身份**:同 Token 下以 `Session-Id` 标识顶层会话;存在 `Thread-Id` 时组合两者,隔离 Codex 主/子代理的 transcript、Response ID、turn lock;无 `Thread-Id` 回退原 `Session-Id` 契约。禁止改用请求体 `session_id`、`prompt_cache_key` 或每回合变化的 request/turn/window ID
- **默认限制**(新安装):下游连接全局 1024、单 Token 64;执行会话 1024;transcript payload 总预算 256 MiB。连接与会话默认按 ~500 并发客户端留量,限额只约束真实存在的资源、不预分配。所有 `responses_ws_*` 整数配置保存 `0` 用内建默认,负数非法;已有数据库记录不迁移
- **生命周期**:上游每 45s 发 Ping,连续 5 min 无帧/Pong 判失活;下游全断满 5 min 后由每分钟清理器关上游物理连接(实际约 5–6 min);稳定逻辑会话与已提交 transcript 在 `responses_ws_session_ttl_minutes`(默认 15,小内存机器可设 10)到期前不因容量/预算压力被逐出
- **超限语义**:达 `responses_ws_max_sessions` 只拒绝新会话身份;已提交 payload 超 `responses_ws_max_transcript_bytes` 后,所有新回合在触达上游前以 `429/rate_limit_error/rate_limit` 拒绝,已准入回合仍可提交,有限最坏超量 `max_sessions × max_body_bytes`
- **连接轮换**:达到 `upstream_connection_reuse_limit_seconds` 的空闲连接立即关闭,在途 turn 完成后再关;下一轮优先原渠道/Key/URL,按需重连并重放完整 transcript——Response ID 只在原物理 WebSocket 上有效
- **`response.interrupt`**:读协程在回合进行中直接拦截，只接受当前回合已向客户端发出的 Response ID；排队中、未知 ID、旧 ID 和已终态请求静默忽略。原生上游 WS 以状态锁内的 live/Response ID 快照作为中断受理点，之后只持写锁发送，避免网络写阻塞 reader 和断开处理；下一回合写入不得越过已受理中断。正在推流时原样透传，以上游 `response.incomplete`(`reason=interrupted`)收尾；HTTP/转换回合在本地取消，按客户端取消记 499、不冷却不换渠道，下发当前 ID 与已收集 output 的合成 `response.incomplete`，同连接可续接。本地中断不得由通用取消写回调关闭下游 WebSocket；正在进行的写仍受既有写超时约束。原生上游已终态或不可写时保留原终态/1011 客户端重放路径，不伪造本地取消成功。`reason=interrupted` 的空 incomplete 不按 599 空流处理。缺 `response_id` 返回 `invalid_request`；无在途回合的合法中断静默忽略。
- **指标**:`/admin/runtime-metrics` 的 `transcript_bytes` 只统计有效 payload,不是 Go 堆占用;另有 `ttl_expired`/`capacity_rejected`/`budget_rejected`/`previous_response_misses` 进程累计计数

## 故障切换(`util/classifier.go` + `cooldown/detection.go`)

- **Responses 缺失历史 reasoning**：HTTP 400/404 或未提交响应的 SSE 错误明确指出某个 reasoning ID 不存在，且该项没有有效 `encrypted_content` 时，基于实际发送的请求体一次删除所有带字符串 ID、加密内容缺失/null/空/纯空白的 reasoning，同渠道只重试一次。有效加密 reasoning、无 ID reasoning、正文及工具调用/结果保持原样；不重复应用渠道请求规则。成功和失败均记录恢复策略及删除数量。原生 WebSocket 的按 ID 重连恢复保持原有契约。

- **Anthropic 工具错误**(`anthropic_retry.go`):仅在未提交响应的 validation 400 明确给出 `tools.N...` / `messages.N.content.M...` 位置（error.param 或 message 前缀）时允许一次 `downgrade_anthropic_tools` 局部重试。定义被拒绝只删除该工具及指向它的 tool_choice，并文本化该工具关联的完整历史调用对；历史块明确不受支持时只文本化该 ID 的一对，保留定义及同名其他调用。调用 ID 必须唯一且调用/结果相邻配对；保留图片、结果错误标记与缓存字段，剩余 tool_result 必须先于普通内容。未知位置、冲突位置、配对/顺序错误、不支持的结果内容或重排破坏缓存 TTL 顺序时走原错误/换渠流程，禁止全量降级；换渠仍使用原请求。思考预算修复和 thinking 兼容重试独立。
- **OpenAI max_completion_tokens**(`openai_wire.go`):上游协议为 OpenAI 的 Chat Completions 请求,型号(剥离 `vendor/` 前缀)为 `gpt-5*`/`o1*`/`o3*`/`o4*` 时,在渠道 BodyRules 之前把 `max_tokens` 改名为 `max_completion_tokens`;两者都存在时保留 `max_completion_tokens`,渠道规则仍可显式写回 `max_tokens`。其他型号未提交响应的 400 明确拒绝 `max_tokens`(`param=max_tokens` 或消息点名该字段,且为 `unsupported_parameter`/提示 `max_completion_tokens`/not supported)时,基于实际发送体改名后同渠道重试一次 `remap_openai_max_completion_tokens`。参照 CLIProxyAPI 的 `NormalizeOpenAIMaxTokens`,但用型号族而非逐模型配置。
- **请求体修复重试的终态**(`proxy_forward.go:forwardAttempt`):非 Anthropic 上游的同渠道修复重试(含多轮)只按最后一次结果决定去向:仍是通用请求拒绝的 400(未命中渠道冷却规则,且 `util.IsGenericRequestRejection` 成立)原样返回客户端,不冷却不换渠;Key/凭证终态、配额、上下文超限等专门分类的 400 以及 429/5xx/网络错误按下列规则正常分类。Anthropic 修复失败按原请求正常分类换渠。
- **Anyrouter Responses 元数据兼容**:上游协议为 Codex、请求属于 Responses 且渠道名称包含 `anyrouter`（忽略大小写）时，转发前仅删除 `input[*].internal_chat_message_metadata_passthrough.content_item_kinds`，保留正文及其他元数据；仅 URL 包含 anyrouter 不触发此规则。

- Key 级(401/403;400 且错误信息含组织已禁用 `organization has been disabled`、余额耗尽 `credit balance`、需身份验证 `identity verification is required`)→ 冷却当前 Key,重试同渠道其他 Key;所有启用 Key 均冷却时自动升级渠道冷却。OAuth 渠道没有独立 Key(`KeyIndex == NoKeyIndex`,凭证就是渠道),Key 级故障直接改为渠道冷却并切渠道;401 例外,先由 OAuth 凭证层强制刷新重试;仅限响应未提交的 401,已提交流的错误帧推断出 401 时按已提交流记日志,不刷新、不在已写出的响应上重放,也不施加凭证失效冷却
- **Anthropic 429 分流**(`util/classifier.go`):响应头明确拒绝共享 5h/7d 订阅窗口 → `CredentialScoped` Key 级冷却(OAuth 即渠道冷却),reset 取自响应头,禁止同渠道 Key 回退;fast 模式缺少 usage credits → 客户端错误,不冷却;其余 429 按模型级。仅 overage 被拒(含 overage claim 且 5h/7d 状态都缺失、利用率缺失或未满)不算共享窗口被拒。reset 超过 7d+1h,或 overage claim 下统一 reset 等于 `Overage-Reset`,都是计费周期边界,不作冷却截止时间,退回指数退避。响应体恰为官方 RPM/ITPM/OTPM 每分钟限流原文(`error.type=rate_limit_error`,忽略大小写与首尾空白,不做子串匹配)且没有任何窗口状态为 rejected 时,同样不用统一 reset,按普通 429 退避且允许换 Key
- **xAI 免费额度耗尽**：`subscription:free-usage-exhausted` / included free usage 错误只有明确提供模型字段或 `for model <name>` 时才冷却该模型；未指向模型的共享额度按 `CredentialScoped` 冷却凭证（OAuth 即渠道）。HTTP 与 SSE 错误采用同一规则，优先保留结构化 reset，缺失时沿用 24 小时滚动窗口上限。
- 模型级(`model_cooldown`,上游 HTTP 400/413/499/5xx/520/524/429,597 服务类 SSE 错误及模型不可用 SSE 错误,598/599 流故障,连接重置/HTTP2 流关闭/空响应/网络超时,404 模型不可用,410 明确模型退役)→ 写入 `(channel_id, 实际上游模型)` 冷却;直接切渠道,不再尝试同渠道其他 Key/URL,不影响其他模型;所有配置模型均冷却时自动升级渠道冷却
- 渠道级(DNS/连接拒绝/网络或路由不可达)→ 切渠道
- **Cloudflare 边缘拦截**(`util/classifier.go`,`cloudflare_challenge`):403/503 质询页(`cf-mitigated: challenge` 或 `Just a moment...`)、403 封锁页,以及 403 的 1010 浏览器签名封禁(纯文本 `error code: 1010`,或 JSON 中 `cloudflare_error=true` 且 `code`/`error_code` 为 1010,或 `error_name=browser_signature_banned`;对齐 sub2api `e0fa4b94f`)由出口 IP/TLS 指纹决定 → 渠道级指数退避,禁止同渠道换 Key,不按模型冷却。普通 JSON 的 code 1010 或正文只提到 1010 仍按普通 403 处理
- 原生协议能力不支持(响应未提交的 HTTP 400 仅限明确的 `RESPONSES_MODEL_NOT_SUPPORTED`、不支持 anthropic-beta 或 `convert_request_failed` + `not implemented`，非模型 404/405，或结构化 500 明确返回 `convert_request_failed` + `not implemented`)→ 写入带 `protocol capability fallback` 标记的代理尝试日志,开启 Debug 日志时同时保存请求/响应详情,但不冷却 Key/模型/渠道/URL;auto 模式可转换时同渠道/Key/URL 探测其他协议,不可转换时切 URL/渠道。普通参数校验、无效 arguments、畸形或空错误体的 400 不视为协议能力缺失，继续按具体 HTTP 错误分类处理
- 客户端错误(406,404 非模型 `does not exist`,400/413/597 上下文超限(含 Anthropic `prompt is too long`),400 图片无法处理(Anthropic `Could not process image`,含 Antigravity/Vertex 包在 `error.message` 里的转发;坏图换渠道仍失败,原样直返让 Claude Code 移除图片后重试),跨协议客户端收到的 Gemini 提示词拦截(无 candidates 只有 `promptFeedback.blockReason`,见下),413 `message_too_big` WebSocket close 1009,Gemini 引用不存在缓存的 403 `CachedContent not found`)→ 直接返回,不重试;普通 HTTP 413 请求体超限仍按模型级换渠
- 成本限额达到 → 跳过该渠道
- Key/模型/渠道共用指数退避:按错误类型取初始值(默认认证 5 min、服务端 2 min、超时/限流 1 min),翻倍并 30 min 封顶;上游或自定义规则给出精确 reset 截止时间时优先使用
- **同渠道重试**(`same_channel_retries`,0–10,默认 0;`proxy_handler.go:tryChannelWithSameChannelRetries` + `proxy_error.go:applyCooldownDecision`):未提交响应的模型/渠道级故障中,仅网络错误与 5xx(596 除外)在本渠道原地再试 N 次,无间隔、每次照常写尝试日志。期间冷却只登记不落库:重试成功即丢弃,用尽或放弃时只提交最后一次尝试的冷却,不因中间失败翻倍退避。是否提交按渠道+模型的跨请求连续失败计数(`sameChannelFailureCounter`,内存态,任一成功清零)判定:超过 N 才冷却。已提交响应的中途断流(599)无法原地重试,靠客户端重发;连续不超过 N 次时不冷却,重发仍可回到本渠道。适用 `retry_other_keys_on_failure` 换 Key 回退时当前 Key 照常冷却。CSV 列 `same_channel_retries`,缺列导入保留原值
- **冷却探测规则**(`cooldown/detection.go`):渠道 `cooldown_detection_rules` 为空时继承系统设置 `global_cooldown_detection_rules`;按 rules 数组顺序(提交后重编号 0..N-1)匹配 status+正则,命名捕获组可解析精确 reset 时间。网络故障故意不进匹配器(没有可信上游错误体);规则命中但不可执行时回退内置分类器,不猜冷却时长。`EvaluateCooldownDetectionRules` 无副作用,代理链路与 admin 规则测试端点共用
- **全冷却兜底**(`selector_cooldown.go`,`cooldown_fallback_enabled` 默认 true):所有渠道都冷却时不直接拒绝,挑「最早恢复」渠道打 `CooldownFallback` 标记继续正常流程,Key 也改选最早恢复的(`SelectCooldownFallbackKey`)。排查「明明全冷却了为什么还在发请求」先看这里;设 false 才直接拒绝
- **日志模型字段**(`model/log.go`+`logs` 表):`actual_model` 记实际发给上游的模型(空=未重定向),`response_model`(`LogEntry.ResponseModel`)记**上游成功响应声明的模型**,三库增量迁移齐全、前端日志页展示;它只用于记录与排查,成本归集、冷却与维度聚合仍以 `ActualModel` 为准
- **OAuth 凭证终态拒绝**(`proxy_forward.go:disableTerminalOAuthCredential`+`admin_oauth_cleanup.go:oauthRefreshTokenRejected`):刷新被上游明确拒绝(Token 端点 401,或 400/403 且错误码为 `invalid_grant`/`invalid_token`/`invalid_refresh_token`/`refresh_token_expired`/`refresh_token_revoked`/`expired_token`,或静态 PAT 本就不可刷新)时直接**禁用渠道**并清零其冷却,再按 `ActionRetryChannel` 切下一个渠道。禁用是凭证快照 CAS(`Store.DisableOAuthChannelIfCredentialMatches`:`WHERE id=? AND enabled=1 AND auth_type=? AND oauth_credential=?`),期间已重新授权的渠道快照不匹配,只打 INFO 跳过,绝不误禁;快照仅因额度等元数据变化而不匹配(`sameOAuthTokens`:access/refresh token 未变)时重读后最多 CAS 3 次;判定不成立的刷新失败仍走普通冷却。所有 OAuth 渠道同账号重新授权 CAS 写入新凭证后统一经 `reactivateReauthorizedChannel` 清渠道冷却并重新启用，回到轮转；模型与 URL 冷却描述的是上游而非凭证，保留不动
- **Responses WebSocket 特例**:
  - 首个语义输出前:非 WS→非 WS、原生 WS→非 WS/原生 WS 均可网关内部切换,WS→非 WS 用 execution session 完整 transcript;非 WS 故障且下一候选为原生 WS 时返回 `status=502` 的 `server_error/upstream_unavailable` 并以 close 1011 断开,让 Codex 客户端完整 replay
  - 已有语义输出后:禁止网关内部切换或重放;成功响应流在终结事件前中断 → `status=502` 的 `server_error/upstream_stream_interrupted` + close 1011,客户端重连并完整 replay 当前 turn;已完成的工具调用先提交 execution session,普通残缺文本不提交
  - 原生上游 WS 的 close 1006、心跳故障、嵌套网关返回的 `upstream_stream_interrupted`,统一按具体 WS 目标连续计数:首次不冷却,10 min 内第二个新物理连接仍失败才冷却 2 min,成功终结事件清零;不得升级为模型冷却

- **容量型 429**：`turn_rate_limit_exceeded`/模型容量错误即使只在 SSE/WS error.code 出现也归为 429，事件与握手的 Retry-After 保留。仅识别出的容量错误按有效 Retry-After（秒或 HTTP 日期）设置精确模型冷却截止时间；普通 429 即使带 Retry-After 也按既有策略指数退避，遵守其上下限；已识别配额 reset 优先，Anthropic 每分钟限流仍沿用指数退避。最终 Codex 429→503 的重试契约不变。

## 自定义状态码(改相关代码前先读语义)

- **499** 客户端取消:不计失败、不冷却,已提交流的部分 usage 照常计费([计费口径](billing.md));上游直接返回 499:模型级冷却
- **管理员手动中断**(`admin_active_requests.go`,`POST /admin/active-requests/:request_id/abort`):`errOperatorAbort` 是独立控制信号,不伪装网络故障、不施加冷却。
  - **未提交响应**:立即终止当前上游,跳过当前渠道的剩余 Key/URL/协议及付费候选,保留下游并切下一渠道(包括 Responses WS 的跨传输切换);无候选则失败。日志记 502
  - **已提交响应**:禁止重放,终止上下游请求并解除阻塞 Write/Flush(`cancelableResponseWriter`)。日志记 599
  - 判据**只看下游提交边界**(`fwResult.ResponseCommitted`),不看 stream 参数或上游是否已回响应头
- **596** 1308 配额超限 → Key 级冷却,不计健康度
- **597** SSE error(HTTP 200+错误体)→ `classifySSEError` 按 error.type 动态判级
- **598** 首字节超时 → 模型级;**599** 流式中断 → 模型级。流空闲超时(`stream_idle_timeout` 全局,`anthropic_stream_idle_timeout` 覆盖)从发请求起计时、每次读到上游字节重置,触发后与总时长超时同归 `ErrUpstreamStreamTimeout`
- **Anthropic 流终态**:上游 `text/event-stream` 已读到字节却正常 EOF,且既无非空 `message_delta.stop_reason` 也无 `message_stop` → 599;给了 `stop_reason` 就算完整,直通不补 `message_stop`。跨协议转换流的客户端是 Claude、Responses 或 OpenAI Chat 时同理(`translatedStreamTruncationDiagnostics`;Chat 终态为非空 `finish_reason` 或 `[DONE]`):上游与转换输出都没有终态就干净 EOF → 599;Gemini 客户端与同协议直通仍只按传输错误判定。下游已提交、上游又没给 SSE error 事件时,向 Anthropic 客户端补写 `error` 事件(`upstream stream interrupted before completion`),让 Claude Code 报错重试而不是把半截回复当完成。Responses 客户端的 HTTP 转换流在转换输出既无终态也无错误事件时补写 `response.failed`(`server_error/upstream_stream_interrupted`,沿用流内 response id 并接续 `sequence_number`;上游给过 error 事件则带其 `error.message`),对齐 sub2api `4355236e0`;Responses WS 回合不补,由 `upstream_stream_interrupted` + close 1011 让客户端重放。OpenAI Chat 客户端同条件补写 `data: {"error":{type:server_error,code:upstream_stream_interrupted}}`,不补 `[DONE]`(它表示正常结束);转换器已输出错误帧的不重复补
- **Responses 首个语义输出**(`proxy_sse_parser.go:isResponsesPreOutputEvent`,对齐 CLIProxyAPI `9e79552f` 的 `isCodexBootstrapBufferableEvent` 与 sub2api `e068c3d02`):元数据事件 `response.created`/`queued`/`in_progress`/`metadata`、`codex.rate_limits`/`codex.response.metadata`,以及内容仍为空的骨架(无文本的 message、无摘要/内容/`encrypted_content` 的 reasoning、空 arguments 的 function_call、空 input 的 custom_tool_call;空 text/refusal 的 `content_part.added`/`reasoning_summary_part.added`)不提交响应,随后的 SSE 错误(如 `server_is_overloaded`)仍可首字节前切渠道。清单封闭:`web_search_call` 等服务端工具条目及未识别的条目/片段类型一律按已输出提交,避免换渠道重放副作用。原生上游 WS 的会话内重连只把元数据视为非语义,空骨架已写入管道,重放会重复条目宣告
- **Responses 空 incomplete**(`proxy_sse_parser.go:isEmptyResponsesIncomplete`,对齐 CPA `IsCodexTerminalEmptyIncomplete`):尚无语义输出时,`response.incomplete` 的 `response.output` 为空且 `usage.output_tokens` 原文恰为 `0`,解析器改记 `server_error/upstream_stream_interrupted` 错误 → 599 首字节前故障转移;直通流、跨协议流、非流式收集器与原生 WS 桥接共用此判定。`incomplete_details.reason=content_filter` 是确定性结果,原样返回,不触发冷却
- **`fwResult.StreamDiagMsg` 是 599 的判定开关,不只是日志字段**:非空即被 `forwardAttempt` 判为流不完整,置 599 并走模型级冷却。所以只有真实上游故障才允许写入,客户端断开必须先过 `isClientDisconnectError`(`buildStreamDiagnostics` 与 Codex 非流式收集器 `codex_wire.go` 各有一处),漏一处就会把 499 误升成 599。`markIncompleteStreamForwardResult` 不覆盖已经是 598 的状态码——两者冷却初值不同
- **流终态有两套判据,判完整就必须给下游完整终止序列**(`proxy_sse_parser.go:parseEvent`+`proxy_forward.go`):除 `[DONE]`/`message_stop`/`response.completed` 外,OpenAI Chat 的非空 `finish_reason`、Gemini 的非空 `finishReason`/`promptFeedback.blockReason`(提示词被拦截;跨协议转换时在提交前改判 400 客户端错误 `upstream blocked the prompt: <reason>`,非流式同理,原生 Gemini 照常透传——否则转换后只剩一条空的正常完成,`translatedGeminiPromptBlockError`)与 Anthropic 的非空 `message_delta.stop_reason` 同样是终态——不少 OpenAI 兼容上游给完 `finish_reason` 就断流,只认 `[DONE]`/`message_stop` 会把完整响应误记成 499/599。判据只有 `openAIStreamPayloadComplete`/`geminiStreamPayloadComplete`/`anthropicStreamPayloadComplete` 一份,直通与跨协议两条路径共用,别再各写一份。语义终态(`IsStreamComplete`)只管判完整;Anthropic/Codex 读到协议最后一个事件提前停读必须看 `IsStreamEnded`(`[DONE]`/`message_stop`/Responses 终态),否则 `stop_reason` 之后的 `message_stop` 与 Chat 尾随 usage/`[DONE]` 会被截掉。而 `openai→{anthropic,codex,gemini}` 转换器的终止事件只挂在 `[DONE]` 上,Gemini 线协议本无 `[DONE]`,但 `gemini→{Responses,Claude}` 在 `finishReason` 后等 usage 或 `[DONE]` 才发终态(上游由 executor 在 EOF 补喂),所以上游省略它时由 `synthesizedStreamTerminator`(OpenAI/Gemini 上游的跨协议转换;转换器在 `[DONE]` 上沿用已记下的 finishReason;上游已报错时不补)在流结束后补喂一份合成 `data: [DONE]` 走同一个转换闭包收尾;Anthropic 上游给了 `stop_reason` 却没发 `message_stop` 时同理补喂合成 `message_stop`(`claude→Responses` 只在它上面发 `response.completed`),Zed 的 Gemini 流在 `stream_ended` 且见过 finishReason 时同样补喂——不手搓终止帧,因为 open content block/stop_reason/usage 都在转换器内部状态里;同协议直通不补,避免改动透传字节。「上游没发 [DONE] 但客户端收到 message_stop」是预期行为
- **429** 统计页/健康时间线计入 ErrorCount 与成功率,`rate_limited` 是 ErrorCount 子集;健康度排序(`GetChannelSuccessRates`/effective priority)排除 429,真实渠道级限流交给冷却过滤。全局设置 `codex_map_429_to_503` 默认关闭;开启后只把所有候选耗尽时返回给官方 Codex 客户端的最终 429 改为 503,内部冷却/统计、其他 Responses 客户端和 ccLoad 自身限额仍保留真实状态

## OAuth 额度输出

- 渠道高级设置 → OAuth 凭证的 `oauth_quota_passthrough`（输出额度信息）默认关闭，旧渠道迁移同样为关闭。仅 Codex、Anthropic 返回账号额度，界面只对二者展示该开关，过滤也只对二者生效；其他 OAuth 渠道隐藏开关并保持原样透传；开启后保留原有透传行为，后台额度查询不受影响；API Key 渠道不受此开关影响。
- 关闭时，在下游输出边界过滤账号额度响应头（Anthropic/Codex/rate-limit）、额度 SSE/WS 事件和协议 JSON 中的额度字段，包括最终错误响应；保留请求 ID、Codex turn-state、正常错误和模型输出。用户自定义 metadata 与 token usage 不作为账号额度删除。
- 原始响应仍先用于内部额度采样、计费、冷却和故障切换，过滤只作用于客户端输出。HTTP、SSE 与 Responses WebSocket 共用该边界；不能在 usage parser 前删事件。
