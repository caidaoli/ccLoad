# 计费、访问控制与 OAuth 配额

修改成本、Token/Key 白名单、额度窗口、采样对账或手动重置时读取。

- **原生 Images 计费**(`proxy_sse_parser.go`、`proxy_util.go:computeRequestCost`):原生 Images 的顶层 usage 保留普通 token 统计，并独立提取 text/image/cache 明细；`cached_tokens_details` 从含缓存的输入明细扣除后计费。已登记图片费率时以图片专项成本替代普通 token 成本，不重复累加 Responses tool cost。flare/sunburst 使用已登记官方费率，不套 Image 2 按尺寸估算。基础 `gpt-image-2.5` 官方独立费率尚未确认（2026-09-10 模型文档返回 404），不假定等同某变体，维持现有普通价格目录/自定义价格回退；该回退不代表已核实的图片专项费率。
- **Anthropic web_search 按次计费**(`proxy_sse_parser.go`、`util.CalculateWebSearchToolCost`):`usage.server_tool_use.web_search_requests` 是累计快照，只采纳正值（与 token 字段同一占位 0 规则），按官方 $10/1K 次、与模型无关计入 `GetToolCostUSD`，经 `computeRequestCost` 的工具成本项叠加到标准 token 成本（不受渠道模型价格覆盖）；搜索结果进入上下文的 token 照常计费。text/plain SSE 回退复制原始字段而非合计，避免 JSON 扫描与 SSE 回退各计一次。web_fetch 无额外费用，不计。

- **OAuth 累计窗口边界校正**(`oauthcost/usage.go:reconcileWindow`):带有效用量的新采样确认同周期、未发生显著用量回退且上游重置时间仍在未来时，在本地周期滚动之前更新成本窗口 `ResetAt`。保留 `StartedAt`、`CountFromAt`，避免移动计数起点后漏掉账本中已有的成本。半窗口容差只用于识别周期，不用于永久锚住旧重置时间；旧采样或缺用量基线的快照不得借此改写边界。真正的周期滚动按原规则开始新区间;用量回退按"OAuth 用量回退证据"处理。

- **OAuth 周期额度成本账本**(`storage/sql/oauth_quota_ledger.go`、`oauthcost/ledger.go`、`oauthcost/rollback.go`):5h、周、自然月窗口的标准成本**只存在账本表** `oauth_quota_cost_ledger`(PK `channel_id, bucket_at 秒, model, window_key`),凭证 `quota_cost_usage` 只存窗口边界、纪元与回退证据。账本保留 `oauthcost.LedgerRetention`=64 天,**与 `log_retention_days` 无关**——日志可以更早清理,额度累计不能随之丢失;这是"限额累计反复少计"的根治点,不要再引入任何"按日志重算窗口成本"的路径。窗口成本 = 账本在 `[max(StartedAt, CountFromAt), ResetAt)` 内按 `WindowMatchesModel` 匹配的行之和;`window_key` 非空的行是 v7 迁移基线(旧凭据当前周期累计减去账本已有行的差额,不读日志),只计入同 key 窗口。账本只追加:边界变化只改变查询区间,不改写行。写入在日志事务内,不锁 channels 行、不解码凭证(Codex 已购额度除外),逐条 `util.USDToMicroUSDSafe` 取整后按主键排序 upsert 累加。`gpt-reserve` 归属仍由实际请求模型决定。CAS 只校验并写入边界,写事务内不扫账本;`persistOAuthUsage` 在 CAS 成功后按 `sampledAt` 求和,使 reset_at 与刚采样的窗口对齐。列表/详情用 `OAuthQuotaCostViews(…, now)` 把过期窗口本地滚到当前周期后求和,不改写凭证:每个渠道按全部计数区间端点切成基本分段,单次扫描在 SQL 端 `GROUP BY 分段, model, window_key`,返回行数与流量无关;账本按秒分桶、行数与请求同阶,不要改回把原始行拉到 Go 侧分配。前端 JSON 形状不变。
- **OAuth 用量回退证据**(`oauthcost/rollback.go`):同周期内上游 used% 下降超过 `upstreamUsageRollbackEpsilon`(1 个百分点)时立即截断(`CountFromAt=采样时刻`),同时记录待定的 `Rollback` 证据(截断前计数起点、截断前读数、截断读数)。判定在 `oauthcost.Reconcile` 合并同周期更新采样时完成,**只比较上游读数,不使用本地成本**——`logs.cost` 随渠道模型价格、模型组合与缓存口径变化,与上游额度百分比没有稳定比例:采用启发式并先判低位:读数 ≤ 截断读数 + ε 时继续待定(含阈值重叠区);明确离开低位后,若读数 ≥ 截断前 − ε 则恢复原计数起点,否则按真实重置保留截断。仅凭读数不能证明重置与否;误恢复时旧读数 ≤ 重置后到判定采样的累计消耗 + ε,这个百分点关系不构成金额上限;待定期间再次回退被吸收,不前移截断点。结案、周期推进、手动重置或纪元越过恢复目标都清除证据。成本读取只求和,不改写凭证。

- **计费口径**(`proxy_error.go:billableResult`):日志成本与令牌费用同源。2xx 按完整响应计费；非 2xx 但响应已提交给客户端且解析到 usage(客户端 Esc 的 499、上游断流/空闲超时的 599、提交后的 SSE error、管理员中断)按已解析的部分 usage 计费——上游已为这些 token 收费，归零会让令牌限额、渠道日限额和 OAuth 窗口一起漏计。未提交的失败会切换渠道重试，客户端没拿到内容，不计费。令牌计数器用 `model.TokenStatsOutcome` 三态：成功/失败各计一次，取消(499)不计次数与耗时(与 logs 聚合排除 499 一致)但仍累加已计费用量；`UpdateTokenStats` 按传入值累加 token 与费用，不计费的调用方传 0。部分 usage 是下界：上游在断开前生成但未回报的输出 token 无从得知
- **渠道倍率** `cost_multiplier`(≤0 归 1):× 标准成本 = `effective_cost`,写日志时快照到 `logs.cost_multiplier` 避免历史污染
- **Auth Token**:`cost_*_microusd`(微美元整数避浮点);`cost_limit` 是总限额,`cost_daily_*`/`cost_monthly_*` 按服务器本地自然日/自然月累计,任一限额启用时必须同时设正数 `max_concurrency`;允许「超额一个请求」;`CCLOAD_API_TOKENS` 启动预置
- **Auth Token 访问控制**(`model/auth_token.go`、`auth_service.go`):`allowed_models` 模型白名单(空=无限制);`allowed_channel_ids`+`channel_restriction_mode`(`allow` 白名单/`deny` 黑名单,空 mode 视为 allow,空列表始终无限制),`ChannelRestriction.Allows` 封装极性,选择链路走 `FilterAllowedChannels`;`max_concurrency` 令牌级并发上限(0=无限),`acquireTokenConcurrencySlot` 获取槽位
- **Key 模型白名单**(`model/config.go:APIKey.AllowsModel`+`proxy_forward.go`+`admin_types.go:normalizeAPIKeyAllowedModels`):`api_keys.allowed_models` 限定单个 Key 服务哪些模型,空/`*` 都是不限制。**和 Auth Token 的 `allowed_models` 同名但不同层**——一个管令牌能请求什么模型,一个管渠道内哪个 Key 能被选中,改代码前先认准层级。比对的是 `resolveChannelRoutingModel` 给出的**渠道逻辑模型**:模糊匹配之后、`redirect_model` 重定向之前,所以白名单填渠道模型名而不是上游模型名;保存时校验模型必须存在于该渠道 `models`,按渠道模型名归一大小写并去重,编码后上限 8000 字节。过滤发生在 Key 重试循环之前,某渠道所有 Key 都不服务该模型时返回 `ErrNoAPIKeyForModel` → **跳过该渠道**,不冷却、不记失败
- **渠道每日限额** `daily_cost_limit`(美元,0=无限);`CostCache` 内存缓存按天重置
- **OAuth 配额成本**(`internal/oauthcost/usage.go`+`app/oauth_quota_cost.go`+`sql/log.go:AddLogWithOAuthQuotaCost`):Codex/Anthropic/Antigravity/xAI 凭证 JSON 的 `quota_cost_usage.windows[]` 内持久化**每个上游额度窗口**的边界;窗口的**标准成本**(不乘 `cost_multiplier`,与 `effective_cost` 无关)由账本在读取时求和(见"OAuth 周期额度成本账本")。槽位身份是上游的 `limit_name|kind`(`oauthcost.Key`),**不是窗口时长**——同一时长可以对应多个互不相干的窗口(Antigravity 的 gemini/3p 周额度、Anthropic 的三个 7 天窗口),按时长归并必然错位。每个槽位带模型族 `Family`,账本行按 `oauthcost.LedgerModel`(`ActualModel` 优先)记录模型,求和时 `WindowMatchesModel` 逐槽判族:Antigravity 按模型名前缀分 `gemini`/`non_gemini`,Anthropic 的 `seven_day_sonnet`/`seven_day_fable` 各自成族,Codex 的 `codex-spark` 只吃 Spark 模型,主 `codex` 窗口使用 `FamilyCodex` 排除 Spark 和 `gpt-reserve`，reserve 窗口使用 `FamilyCodexReserve` 仅吃 `gpt-reserve`,其他未分族窗口才使用 `FamilyAll`。窗口边界只来自上游额度采样(月=28–31 天区间,按自然月+`ResetDay` 锚点推进)后由 `Reconcile` 对账,没采到就没有窗口、不计成本(账本行仍然写入,窗口出现后即可求和);采样里消失的槽位丢弃,但**一个有效窗口都没采到时保留已有窗口**(缺信息≠窗口消失)。只有落在 `[max(StartedAt, CountFromAt), ResetAt)` 半开区间的账本行计入,迟到的旧日志不会污染新周期。混合存储副本走 `AddLogReplica` 不写账本;SQLite 权威账本按分钟切片(key `oauth-quota-ledger/<sliceStart>`,片越宽重写放大越大)异步替换到主库,全量对账按 6 小时时间片比对 64 天、只重写有差异的切片,启动首次导入随配置表恢复;凭证仍由 `markChannelDirty`→`syncChannelReplica` 复制
- **CodeBuddy 余额**：不参与 `oauthcost` 标准成本对账；个人渠道查询资源包，企业渠道查询 `get-enterprise-user-usage` 的 `limitNum-credit`，保留小数，`limitNum=-1` 为无限额度。安全快照持久化 `remain/used/total/unlimited`，列表复用管理账户进度条显示已用、总额和可用比例；无总额或无限额度时不画百分比。查询复用 OAuth 渠道的单个、批量和活跃刷新链路。
- **Codex 购买额度**：本次上游 `codex.rate_limits.credits.has_credits=true` 且同一事件的 `rate_limits.primary` 或 `secondary` 的数值 `used_percent >= 100` 时，才把该请求全部标准成本计入 `quota_cost_usage.credit_standard_cost_microusd`，不计入任何 5h/周/月窗口。仅持有 Credit、窗口尚未耗尽或缺少有效窗口使用率时仍按窗口记账；不以 `allowed`、`limit_reached`、代码审查或其他附加额度组替代本次窗口判据。日志字段 `codex_has_credits` 表示该请求按此规则归属 Credit，账本写入排除这些日志。Credit 累计独立于窗口周期及手动窗口重置，展示的是本地标准成本，不是上游 credits 余额或实际扣款；已有历史记录不推测迁移。
- **Codex 周窗口换位**(`oauthcost/usage.go:reconcileCodexWeeklyKey`):主额度可能从 `primary=5h,secondary=7d` 变成 `primary=7d` 或反向变化。对账前只迁移主 `codex` 的对应 7 天窗口,保留 `StartedAt` 与 `CountFromAt`,随后仍按采样回退/周期滚动规则判断是否开始新区间;普通账本行按模型匹配,自然随窗口走,v7 基线行按旧 key 记录,换 key 后成为孤儿(仅影响迁移后首个周期,已知限制);不把 5h、Spark 或其它额度组的成本移入周窗口。旧布局采样不得回写或通过缺失窗口清理删除较新的窗口
- **Codex 活跃额度身份决定通用窗口归属**(`app/codex_usage_headers.go:codexPassiveLimitScope`):通用 `X-Codex-Primary/Secondary-*` 与 SSE `rate_limits` 描述的是"本次请求实际计量的额度"，显式 `metered_limit_name` 优先，缺失时继承 `X-Codex-Active-Limit`；两者均缺失且实际发送模型为 `gpt-reserve` 时归属 reserve。其余归属由额度身份决定：为空、`premium`（主额度）或 `codex` 时才写入并替换主 `codex` 作用域；实测 `base_model_inference` 与 `gpt-reserve` 归属 `gpt-reserve`，通用窗口只更新 reserve，不能写入主额度；其他未知身份不写主作用域，也不按值另建分组。其他附加组只从明确命名的 `X-Codex-<分组>-*` / `additional_rate_limits` 块采集；HTTP 中活跃身份命中命名组时替换该组。不能用"同一响应里是否出现完全一致的附加组"证明别名——上游可省略附加块、改用内部代号或让字段略有差异，任一情况把 reserve 的低使用率写进主额度都会被 `oauthcost` 当成提前重置而截断主额度的账本计数区间。未知身份宁可丢弃被动样本，由下一次官方 `/wham/usage` 刷新补齐。主额度回退按上述证据规则处理，周期滚动开始新区间。
- **OAuth 配额采样完整性**:Anthropic 被动响应和 xAI 周/月端点部分失败走 `ReconcilePartial`,保留未返回窗口;完整快照也不得删除采样时间比它更新的窗口。退休截止取有效窗口 `SampledAt` 与请求完成时间的最早值,避免 Codex reset credits/Anthropic profile 请求延迟掩盖旧额度采样。Codex 展示合并按单窗口采样时间判新旧,只匹配官方已有的同 key 窗口;同正时长的同周期抖动保留官方边界,旧周期已结束且被动样本落在向前推进的新周期内时,同步采用新比例及重置时间以关联新累计成本。套餐或上游策略引起时长变化时,较新被动样本须落在自身 `[reset_at-limit_window_seconds, reset_at)` 内,同时更新时长、比例和重置时间,允许新截止早于旧截止;若官方同额度组的另一槽位已有该新时长,则保留原布局等待完整快照确认,避免把槽位换位变成重复额度。不新增被动独有窗口,不合并不同额度组;旧样本、未知边界、已结束或尚未开始的跨时长周期不能覆盖官方值
- **渠道列表额度同步**:列表加载成功后更新已有 ready 额度缓存,让被动比例与累计金额持续更新;仅接受最新发起的列表请求,且不得覆盖请求期间完成的手动/自动额度刷新或正在进行的重置。每次普通列表加载都重新采样当日活跃渠道(切换筛选、翻页、手动刷新列表均再次触发),`activeChannelUsageAutoRefreshPendingIDs` 只跳过同一渠道尚未返回的在途请求,不得记录"本会话已刷新"之类的跨次去重——额度窗口会滚动,缓存快照不能代替重新采样。单个 OAuth 额度刷新、Codex 额度重置和手动批量额度刷新完成后,列表重载传入 `refreshUsage: false`,避免级联触发整页自动额度刷新;普通列表加载仍保留自动刷新及失败后重试。同步只替换额度数据,保留操作状态,不清理或重算历史成本
- **检测额度与成本**:定时检测、手动检测及管理对话复用普通请求的 Codex/Anthropic 被动额度采样规则；检测中的 Codex 响应体采样同步保存，保证额度窗口先于检测日志落库，首次检测成本也能计入。检测日志按实际上游模型写入账本，窗口标准成本由账本按模型和边界求和。
- **Codex 手动配额重置**(`admin_codex_quota_reset.go`,`POST /admin/channels/:id/codex-quota-reset`):先查上游 reset credit,无可用额度返回 409;credit 一经消费不可退,之后的本地清理(成本窗口重置、渠道全部冷却清除、额度刷新)全部 best-effort,失败只进响应 `warnings` 而不回滚。同渠道并发重置由 `codexQuotaResetInFlight` 直接 409 拒绝。手动重置只把窗口 `CountFromAt` 设为重置时刻并清除回退证据;成本由账本按新区间求和,不回放日志
- **Codex 额度身份与纪元**(`oauthcost/usage.go`、`codexauth/credential.go`、`admin_oauth_usage.go`):`quota_cost_usage.identity` 记忆 id_token 的 `account_id|plan_type`,独立的 `account_id` 不随 poll 套餐去重清空。刷新/重新授权比较账号和套餐,账号变化即使缺少套餐字段也重置;`upstream_plan_type` 只与上一主动快照的原始套餐比较,不与凭证或展示套餐混用。新纪元丢弃旧窗口、主动和被动快照;poll 触发时清空完整身份、保留账号，并持久化轮询前的声明身份；同账号旧声明到达时继续等待，首次变化的声明只补记、不再次重置。连续多次套餐变化而声明跨次滞后时，没有两来源共享的变更标识，仍不能完全关联各次变化。`epoch_at` 是秒级成本下限,`epoch_at_unix_nano` 是同秒事件的顺序屏障;纪元单调推进,窗口只有起点早于纪元时抬高 `CountFromAt`,后续完整周期不重复盖章。无窗口的手动重置也落盘;只有快照时先建窗,bootstrap 保留纪元,后续采样从纪元后的账本行求和。主动采样携带实际凭证账号与刷新后真正发请求的时间,每次 CAS 重试都拒绝早于纪元的请求/窗口采样或其他账号响应;poll 纪元取额度窗口实际采样时间,不取辅助 reset credits 请求的延迟完成时间。被动 HTTP/SSE 携带请求所属账号与纪元进入持久化/异步队列,拒绝跨纪元或跨账号响应,去重水位在持久化成功或确认库中状态无需变化后推进；拒绝的旧纪元采样不推进。旧状态由 Normalize 补记账号及未开纪元时的身份,无需数据库迁移。

- **自定义模型价格**(`util/custom_model_pricing.go`,设置键 `model_custom_pricing`):按模型 ID **整份替换**系统价格,不是增量合并。可表达的字段就是 8 个价目:基础四价(`input_price`/`output_price`/`cache_read_price`/`cache_write_price`)与高上下文四价(`input_price_high`/`output_price_high`/`cache_read_price_high`/`cache_write_price_high`,阈值由 `getTierThresholdForModel` 按模型名前缀内置)。固定按次费率(`fixed_cost_per_request`)只由系统目录维护(图像模型),自定义契约不提供该字段,`validateCustomModelPricing` 对非零值直接报错——否则程序化调用能塞进一个前端无法编辑、却覆盖系统图像计费的值。缓存价与缓存创建价都没有启用开关,也不接受布尔字段:填了(含显式 0)就按填的值算,留空则按基础价 × 系列倍率回退;1 小时缓存创建价恒为「生效输入价 × 2」,不单独配置。**只有真正的多档分层表不可覆盖**:三档及以上(或末档带真实上限,如 `qwen-flash` 的 1M)的表无法用两档表达,而 Qwen 全系(`qwen3-max`/`qwen3-vl-*`/`qwen3-coder-*` 等)基础价为 0、价格只存在于分层表里,一旦允许覆盖就会丢掉中间档导致计费归零或降档。`validateCustomPricingTarget` 在 `ParseCustomModelPricing` 与 `InstallCustomModelPricing` 两个入口都拒绝覆盖这类模型,前端在预填默认价时同样跳过并提示。**两档且末档无上限的表会在快照构建时折叠**成基础价 + 高上下文价(`collapseTwoTierHighContextPricing`):内置目录(`buildModelPricingSnapshot`)与远端 overlay(`overlayRemotePricing`)两条路径都必须折叠,否则同一模型的可覆盖性会在目录同步前后翻转。**折叠只换表达方式,不改计费语义**:GPT-5.6/GPT-6 系(以及 gpt-5.4/5.5/grok-4.5)长上下文仍是**分段计费**——超过阈值后整个请求改按高价算(上游 `tier.type=context`),不是前段按基础价、超出部分按高价累加;两条路径在阈值边界、缓存读、缓存创建上逐点等价。折叠的硬前提是档位边界等于 `getTierThresholdForModel` 推导出的阈值(否则阈值静默漂移),因此 GPT-5.6/GPT-6 系在 `getTierThresholdForModel` 里必须有 272K 分支——加新前缀模型时两处要同时改。折叠保留 `CacheReadCountsTowardTier`,OpenAI 系正是靠它把缓存读计入阈值判定。分段行为本身由 `TestCalculateCost_OpenAIContextTieredPricing` 断言,与表达方式无关。**图像费率不参与自定义**:图像字段的解析、校验、序列化与前端编辑全部移除,`CalculateImageGenerationToolCost`/`CalculateImageGenerationToolFallbackCost` 只查系统目录(`imageGenerationToolPricingByModel`/`imageGenerationFallbackCostByModel`),避免自定义覆盖把图像成本静默归零。前端 `projectCustomPricingDefaults` 在预填系统价格时按契约字段白名单投影,系统内部字段(`token_pricing_tiers`/`has_cache_read_price`/`cache_read_counts_toward_tier`/图像字段)不会混进提交体。改这里时别只看 `ModelPricing` 结构体——`TokenPricingTiers`、`CacheReadCountsTowardTier`、`HasCacheReadPrice`、图像字段仍是系统内置机制,只是不再对外暴露为可配置字段
- **长上下文分档输入**：`CacheReadCountsTowardTier=true` 时，阈值按 input、cache_read 与 5m/1h cache_creation 之和判断。Claude 长上下文（`claude-sonnet-4-5`/`4-0` 的 200K）遵循 Anthropic 的完整 prompt 口径。models.dev 的 openai 与 anthropic context tier 同步后保留该标志，Gemini 等其他 provider 仍只看非缓存输入。
- **自定义价格分档语义**：覆盖价目时，从当前系统目录（包括别名与前缀匹配）保留 `CacheReadCountsTowardTier`，目录刷新重建快照时重新取值。`input_price_high` 显式为 0 仍启用高档，由内部 `HasInputPriceHigh` 保留存在状态；未填写且值为 0 才不启用。两档系统表折叠时同样保留该状态，保证免费高档仍按原表计费。
- **渠道模型价格**(`model/config.go:ModelEntry.Pricing`、`channel_models.model_variants`、`util.CalculateStandardCostBreakdownWithPrice`):字段契约与全局自定义价格相同(`util.CustomModelPrice`,8 个价目),但 `CustomModelPrice.ModelPricing` 额外要求 `input_price`/`output_price` 必填、填任一高上下文价时 `input_price_high`/`output_price_high` 必填(与编辑器同规则;API、CSV、批量导入与存储读写都经过它,否则只填缓存价会按 0 计费),挂在渠道模型**选定行**上,优先级 渠道价 > 全局自定义 > 系统目录,**整份替换**价目(固定按次费率随之失效),缓存读是否计入分档仍取计费模型的系统语义。行身份为渠道逻辑模型+目标模型(大小写无关、目标剥思考后缀),不是单独的逻辑模型名;渠道模型 `*` 不能保存。它替换的是标准成本 `logs.cost`,渠道/Key `cost_multiplier` 照旧叠加;OAuth 额度窗口、渠道日限额、令牌统计都读同一个 `logs.cost` 口径,`tryChannelWithKeys` 按渠道尝试快照到 `reqCtx.attemptModelPrice`,日志与令牌统计共用。管理测试(非流式、流式对话、Cursor)入口经 `bindChannelTestBilling` 快照选定行的 `ChannelModelPrice` 与重定向前的 `RequestModel`,成本统一走 `channelTestCostUSD`:与代理同一 `ResolveBillingModel(实际上游模型, 请求模型)`、同一 `resolveBillingServiceTier`(请求体声明 + 上游回显)、同一 `computeRequestCostWithPrice`;计费模型决定高上下文阈值与缓存回退倍率,测试不能只按上游模型或逻辑模型算。service_tier 倍率叠加在渠道价上,Anthropic fast 对渠道价按 input/output ×2、缓存保持基础价(全局自定义价格在 fast 模式下仍走官方 fast 固定价)。与全局自定义不同,渠道价允许覆盖系统分层表模型——这是用户对该渠道的显式价格,不存在"静默丢档";前端预填(`/admin/model-pricing?effective=1`,含全局覆盖,不缓存)遇分层表只提示手填。批量替换导入、上游模型刷新、Antigravity 重新授权、旧版 CSV(无 `model_entries_json` 列)都用 `CarryModelPricing` 按行身份沿用已有价格;存储里损坏的价格读取时报错,不回退全局价格。日志明细 `cost_breakdown` 按渠道**当前**价格重算,只作展示。
