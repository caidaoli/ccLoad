# 显式渠道权重替代可用 Key 数

同一渠道优先级档内原本按可用 Key 数分流，多 Key 渠道（如 10 个 Key 的 gemini-decision）会独占大部分首选流量，降低渠道优先级又会让它闲置。因此新增渠道权重：0 表示自动权重，沿用可用 Key 数，存量行为不变；大于 0 时按这个固定值分流，部分 Key 冷却也不缩减份额（Key 全部冷却时渠道本来就会被过滤）。Key 权重只在渠道内的同一 Key 优先级档内生效，不参与渠道权重计算，两层互不影响。

## Considered Options

- **权重 × 可用 Key 数**：默认值 1 时与现状一致，但要压低多 Key 渠道，就得给其他渠道设很大的倍数，份额也不直观。未采用。
- **渠道自动权重取 Key 权重之和**：会把“渠道之间怎么分”和“渠道内部怎么分”混在一起，调 Key 权重会意外改变渠道份额。未采用。
