ccLoad

A self-hosted AI API gateway: many accounts and API keys behind one stable endpoint

Point Claude Code, Codex, Gemini, or any OpenAI-compatible client at ccLoad by changing the base URL. When a key is rate-limited or an upstream fails, ccLoad moves to the next usable channel and records what every request cost.

What it is and how it works

ccLoad is a service you host yourself. It sits between your AI clients and the model providers: clients talk to one address, and ccLoad decides which upstream handles each request.

Connect upstreams

Add channels in the admin console: paste API keys, or import account credentials for Codex, Claude, and other providers.

Issue access tokens

Create a ccLoad token for each client or teammate, with optional model, channel, cost, and concurrency limits. Upstream keys never leave the gateway.

Change the base URL

Point the client at ccLoad. It picks a channel by priority, converts the protocol when needed, and moves to the next channel on failure.

What it solves

🔄

Rate limits and outages stop interrupting work

Configure several channels and keys for the same model. On a rate limit, auth failure, or upstream error, ccLoad cools down only the failing key or model and hands the request to the next usable channel.

🔀

Any client, any upstream

Anthropic, OpenAI, Codex, and Gemini clients can all use any channel that serves the model. When the upstream speaks a different protocol, ccLoad converts the request and the streamed response.

🔑

Upstream credentials stay in the gateway

API keys and account credentials are stored only in the gateway. Clients and teammates get ccLoad tokens that can be limited by model, channel, cost, and concurrency, and revoked at any time.

💰

Spending you can see and cap

Every request records its model, token usage, cost, and first-byte latency, with statistics by channel, model, and token. Channels take a daily cost limit; tokens take total, daily, and monthly limits.

Core Features

Routing and failover

🎯

Smart Routing

Higher-priority channels first; equal priority uses smooth weighted round-robin by usable keys. Optional health and first-byte scoring.

🔄

Auto Failover

Isolate failures at key, model, channel, or URL scope. 401/403 cool only the current key; model-scoped errors do not disable the whole channel.

🛡️

Soft Error Detection

Detect errors disguised as HTTP 200. Explicit rate-limit markers in SSE streams are handled as 429.

🌐

Per-channel Proxy and Windows

Route a channel through HTTP, HTTPS, or SOCKS5, and optionally restrict it to an HH:MM availability window. Outside the window it is excluded from routing.

Protocol and client compatibility

🔀

Automatic Protocol Fallback

Try the client protocol first, then probe OpenAI, Anthropic, Codex, and Gemini without retrying it.

🔗

Responses WebSocket

Keep one Codex client WebSocket while ccLoad bridges native WebSocket and HTTP/SSE upstreams with transcript-aware failover.

🧠

Thinking Suffix

Append (high)/(xhigh)/(16384) to a model name to set thinking parameters across protocols. Routing, cooldown, and the upstream name always use the base name.

⚡

Local Token Count

<5ms response, 93%+ accuracy, count tokens without calling upstream.

Accounts, cost, and monitoring

🔑

OAuth Channels

Connect Codex, Anthropic, Antigravity, xAI, CodeBuddy, Z.ai Coding Plan, Cursor, and Zed accounts. Refresh quotas and balances from the channel list.

🗝️

Per-Key Model Allowlists

Restrict which channel models each key serves. If every key declines the model, the channel is skipped with no cooldown and no failure recorded.

💰

Cost Control

Global and per-channel custom model prices, per-key multipliers, daily channel limits, and token total/daily/monthly limits. Track OAuth quota windows against upstream reset times.

📊

Real-time Monitoring

Seven-day service health, client-protocol statistics, cost analysis, trends, and live request monitoring.

First-party account channels

Import credentials in the admin console. Clients never hold upstream keys. OAuth authorization and refresh still use official endpoints; optional system settings override data-plane addresses.

💬

Codex / ChatGPT

OAuth or a personal access token (PAT). PATs start with at- and are verified on import. A permanently rejected refresh disables the channel.

🟠

Anthropic / Claude

Claude OAuth credentials refresh automatically. Quota windows and standard-cost tracking follow the upstream reset schedule.

☁️

Antigravity

Google Cloud Code channels with a fixed daily → daily sandbox fallback. Capacity exhaustion cools the current model first.

⚡

xAI

Grok OAuth channels. Conversational models at grok-4.6 and later can use the Images API through the image_generation tool.

🧩

CodeBuddy

Scan to sign in or import workbuddy.json credentials. Fetch account models, refresh tokens automatically, and refresh balances from the channel card. China accounts also support daily check-in.

🧩

Z.ai Coding Plan

Browser authorization or a Coding Plan API key. The model catalog is loaded from the account; quota windows are not billed as standard cost.

🖱️

Cursor

Import a Cursor user API key. ccLoad installs the official SDK Bridge when needed and does not run Cursor built-in tools on the gateway host.

⌨️

Zed

Native app sign-in over an ephemeral RSA keypair; the callback token is decrypted into a long-lived credential. Trial access binds the real Zed installation system ID. A fixed /completions upstream runs Codex-protocol local transforms.

Not a black-box proxy

ccLoad puts channels, OAuth credentials, models, tokens, cost, first-byte latency, failure reasons, and model verification into one console. Administrators manage the gateway; API-token users get a read-only view scoped to their permitted channels and usage data.

  • Track requests, tokens, cost and latency system-wide as an administrator or within one API token's scope.
  • Run chat-style tests or test models by channel through the real proxy path, including reasoning level, built-in search, and image generation.
  • Configure multiple URLs and keys, import OAuth credentials, pause individual models, set per-key model allowlists, and enforce RPM, concurrency, time windows, and daily cost limits.
  • Export conversations as Markdown or HTML, then inspect masked upstream requests and responses when tracking protocol transform issues.

Quick Start

bash 
# Download docker-compose.yml and the .env template
curl -o docker-compose.yml https://raw.githubusercontent.com/caidaoli/ccLoad/master/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/caidaoli/ccLoad/master/.env.docker.example

# Edit .env and set the admin password (required, service exits without it)
nano .env  # set CCLOAD_PASS=your_password

# Start the service
docker-compose up -d

# Open the admin console
# http://localhost:8080/web/
steps 
1. Sign in to Hugging Face: https://huggingface.co
2. Create a new Space: New Space -> Docker -> SDK: Docker
3. Create Dockerfile:
   FROM ghcr.io/caidaoli/ccload:latest
4. Configure environment variables (Settings -> Variables):
   CCLOAD_PASS=your_admin_password
5. Wait for the build to finish (about 2-3 minutes)
6. Open your Space URL
