Startup Environment Variables

Environment variables cover bootstrap configuration only — values ccLoad needs before a database connection exists. Storage variables (SQLITE_PATH, SQLITE_JOURNAL_MODE, CCLOAD_MYSQL, CCLOAD_POSTGRES, CCLOAD_ENABLE_SQLITE_REPLICA, CCLOAD_SQLITE_LOG_DAYS) decide how the database is opened, so they cannot live inside that same database and will stay environment variables. Runtime policies belong in the admin console below.

Variable Default Purpose Recommendation
PORT 8080 HTTP listen port. Hugging Face Spaces must use 7860.
CCLOAD_PASS None Admin console password. The service exits when it is not set. Required in production. Use platform Secrets or Docker Secrets.
CCLOAD_API_TOKENS None Pre-provisions API access tokens at startup. Supports token|description. Useful for automated recovery. Prefer the token page for normal management.
API_TOKENS None Compatibility alias for CCLOAD_API_TOKENS. Do not set it to a different value from CCLOAD_API_TOKENS.
CCLOAD_RELEASE_BASE_URL None Complete .../releases/latest/download base URL used for stable release detection and all release asset downloads. Leave unset to let the update manager try gh.monlor.com, fastgit.cc, ghfast.top, then GitHub. Preview metadata always comes from GitHub's Releases feed. Set this only to force one private mirror for stable metadata and all release asset downloads.
CCLOAD_MYSQL None MySQL DSN. Mutually exclusive with CCLOAD_POSTGRES. Set exactly one primary DSN; when neither is set, ccLoad uses SQLite.
CCLOAD_POSTGRES None PostgreSQL DSN in URL or libpq keyword format. Mutually exclusive with CCLOAD_MYSQL. Example: postgres://user:pass@host:5432/ccload?sslmode=require.

Storage Modes

Choose storage by deployment shape. Do not add an external database just to look production-grade; SQLite is simpler and has less operational surface for single-instance deployments.

Mode Configuration Use Case Trade-off
SQLite only Do not set a primary DSN Local development, personal deployments and single-instance services. Simplest path; not suitable for shared multi-instance state.
MySQL only Set CCLOAD_MYSQL Standard production, external backups and migration across machines. Strong persistence; read/write latency depends on the database.
PostgreSQL only Set CCLOAD_POSTGRES PostgreSQL-based production, external backups and migration across machines. Strong persistence; read/write latency depends on the database.
Hybrid Primary DSN + CCLOAD_ENABLE_SQLITE_REPLICA=1 Hugging Face Spaces or a high-latency primary when persistence is still required. Durable data uses the primary and reads use local cache; higher complexity.

Channel Configuration

Channels are ccLoad's core runtime objects. Every channel accepts four client protocols and owns multiple keys and URLs, plus independent cooldown and RPM/concurrency limits. First-party providers use auth_type (codex_oauth, anthropic_oauth, antigravity_oauth, xai_oauth, codebuddy_oauth, zai_oauth, cursor_oauth, zed_oauth) instead of a static API key.

Core fields

  • name: readable channel name used by logs and statistics.
  • protocol_transform_mode: auto starts with the client protocol, then detects OpenAI → Anthropic → Codex → Gemini without retrying it; upstream is client-protocol passthrough-only; local translates to URL-declared protocols, with declared Codex promoted for Responses requests from official Codex clients.
  • urls: an ordered list of URLs with optional protocols. Local mode prioritizes declared URLs; if all are undeclared it tries Anthropic → Codex → OpenAI → Gemini. exact: true disables automatic path joining.
  • api_key: supports one or multiple keys. Each key may set allowed_models to restrict which channel models it serves; empty or * means unrestricted. Matching uses the channel logical model (after fuzzy match, before redirect_model). Each key may also set cost_multiplier (default 1, 0 = free) applied to that key's usage for effective-cost limits and accounting.
  • models: each entry can redirect to a different upstream model or be disabled independently. A disabled entry stays persisted but is excluded from routing and fuzzy matching.
  • priority: higher priority is selected first; equal priority uses smooth weighted round-robin.
  • proxy_url: optional per-channel proxy. Supports http, https, socks5 and socks5h; empty uses the process environment proxy.
  • available_time_start / available_time_end: optional server-local daily availability window in HH:MM; leave both empty for all day, and overnight windows such as 22:00–08:00 are supported.
  • websockets: for channels with a Codex-capable URL. Reuse a native upstream Responses WebSocket; use the built-in detector before enabling it.

Protection fields

  • rpm_limit: rolling 60-second request cap for the channel; 0 means unlimited.
  • max_concurrency: maximum in-flight requests for the channel. Streaming requests release the slot only when the stream ends.
  • daily_cost_limit: daily channel cost limit. The channel is skipped after the limit is reached.
  • cost_multiplier: for OAuth channels the credential is 1:1 with the channel, so the multiplier stays channel-level; for api_key channels it lives on each key.
  • scheduled_check_enabled: enables daily scheduled probing, usually paired with scheduled_check_model. scheduled_check_interval_minutes accepts 1–1440 whole minutes (default 300), and scheduled_check_start_time uses server-local HH:MM (default 00:00). Checks run from the start time at the configured interval until the day ends; missed checks are skipped.
Auto mode learns protocol capability at runtime. For each URL and request family, ccLoad tries the client protocol first, then falls back through OpenAI, Anthropic, Codex and Gemini while skipping the protocol already attempted. A working protocol remains cached until restart or channel configuration changes; an all-unsupported result is probed again after 10 minutes. It advances only after an uncommitted HTTP 400, a non-model 404/405, a structured 500 with convert_request_failed plus not implemented, a pre-origin Cloudflare 403 block page, or a transform that cannot represent the request. Exact URLs marked with # translate directly when a conversion exists. Choose upstream or local when the route must be strict.
Multiple URLs are channel-internal resilience, not a replacement for channel priority. ccLoad explores URLs first, then selects by 1/EWMA latency weighting. Failed URLs back off independently and do not drag down other URLs in the same channel.
Thinking suffixes are client syntax, not model identity. Request claude-sonnet-4-6(high) or gpt-5.2(xhigh); ccLoad strips the suffix for routing and writes the level into the upstream protocol's thinking fields. Channel model lists do not need suffixed entries. Custom request rules run later and can override those fields.
An explicit channel-wide fixed-window quota is treated as a real channel cooldown. When the upstream provides a concrete channel reset time, ccLoad waits for that reset instead of guessing with exponential backoff.
Provider-specific failures belong in channel cooldown detection rules. Rules run in priority order and the first match wins. Match status and response text, choose key/model/channel scope, then use a fixed duration or parse the provider's reset time. Test an unsaved rule against a raw response or standard upstream log before saving; no match or an unusable reset time falls back to the built-in classifier.
Bulk model cleanup is explicit. After refreshing selected channels, the console can lowercase model names or remove source prefixes in one operation. Review the selected channels first because these actions change the persisted model list.

Runtime Settings in the Admin Console

These settings are stored in the database and can be adjusted from /web/settings.html. Saving a change writes the new value and restarts the process about two seconds later; the restart is what applies it. Saving either model_multimodal_fallback or model_custom_pricing on its own applies immediately without a restart. Saving multiple settings together still restarts the process. In-flight requests finish before the process exits.

Retries and cooldown

Initial cooldown durations are settings, not environment variables: cooldown_auth_seconds, cooldown_server_seconds, cooldown_timeout_seconds and cooldown_rate_limit_seconds, bounded by cooldown_min_seconds and cooldown_max_seconds. An inverted floor/ceiling pair falls back to both defaults. Key errors (401/403) cool only the current key. Model-scoped errors — structured model_cooldown responses, ordinary upstream HTTP 400/413 and 5xx, key-level 429 rate limits, model-unavailable 404, and explicit model-retirement 410 — cool only the actual upstream model. Context-length errors and WebSocket message_too_big return directly to the client without failover or cooldown. The channel is cooled only after every enabled key or every configured model is cooling. Network failures plus internal 598/599 errors remain channel-scoped. cooldown_fallback_enabled (default true) picks the earliest-recovering channel when every candidate is cooling.

Protocol timeouts

upstream_first_byte_timeout limits time to the first valid streaming content, stream_timeout limits total stream duration, and non_stream_timeout defaults to 120 seconds. A zero value disables each global limit. Anthropic, Codex, OpenAI and Gemini can override first-byte and non-stream limits; zero on an override inherits the global value.

Upstream connection lifetime

upstream_connection_reuse_limit_seconds limits how long HTTP/1.1, HTTP/2 and WebSocket connections may be reused. 0 keeps the existing unlimited behavior. At the limit, idle connections close immediately; active connections stop accepting work and close after draining, while new requests reconnect on demand.

Health-based sorting

When enabled, ccLoad subtracts a confidence-weighted failure penalty from priority. Optional TTFB scoring also penalizes channels slower than the current candidate median without applying full weight to small samples.

Token limits

Auth tokens can restrict models, cap concurrency and cost, and scope statistics. Channel access combines allowed_channel_ids with channel_restriction_mode: allow treats the list as an allowlist, while deny treats it as a denylist. An empty list is unrestricted in either mode. Costs use integer micro-dollars to avoid floating-point drift.

Custom request rules

Rewrite headers and JSON bodies per channel with remove, override and append operations. Authentication headers are protected and CRLF injection is blocked.

Channel checks

Manual and scheduled checks both count toward channel RPM limits. Use a low-cost, stable model for checks.

Concurrency and body limits

max_concurrency caps simultaneous proxy requests; max_body_bytes and max_image_body_bytes cap request bodies for regular and Images API paths respectively. http_read_timeout_seconds covers the complete downstream header and body read (0 uses 120 seconds) and returns 408 on timeout — independent of the body-size limits. All take effect after the automatic restart that follows a settings change, and the body limits also bound Responses WebSocket frames and transcripts.

WebSocket sessions

New installs cap downstream WebSocket connections at 1024 globally and 64 per token, retain 1024 execution sessions, and budget 256 MiB of transcript payload. Saving 0 on any of these settings uses that built-in default; negative values are rejected. responses_ws_session_ttl_minutes defaults to 15. A stable Session-Id, combined with Thread-Id when present, isolates transcripts and turn locks. Runtime usage is exposed by GET /admin/runtime-metrics.

Multimodal fallback

model_multimodal_fallback maps a text model to a fallback model for requests that carry non-text content. Keys are normalized by base name with thinking suffixes stripped; up to 64 mappings within 8 KB. It rewrites the incoming model before thinking suffixes, token allowlists, channel filtering and cooldown checks, so routing, logging and cooldown all follow the fallback model. Detection uses the full client-protocol body on HTTP and the complete transcript on Responses WebSocket. Saving this setting on its own applies without a restart.

Model catalog sync

model_catalog_sync_interval_hours refreshes models and pricing from models.dev every 6 hours by default. Set it to 0 to disable network sync; startup falls back from the last-good cache to the embedded catalog.

Custom model prices

Open the custom pricing editor in Settings to set input, output, cache-read and cache-write prices in USD per million tokens, plus optional high-context prices. model_custom_pricing replaces the model's system price entry as a whole. Enter 0 for a free cache rate; leaving a cache rate blank uses the model-family fallback. High-context thresholds follow the system model rules.

Saving prices from the editor applies immediately without a restart. Catalog refreshes preserve your overrides. Remove an override to restore the system price. Models with pricing tiers that cannot fit the two-level editor are rejected; image-specific and per-request prices remain managed by the system catalog.

When the same model costs different amounts on different channels, open the $ button on a model row in the channel editor to set a channel price with the same fields. It applies only to that model on that channel, takes precedence over the global override and the system price, and is still multiplied by the channel or key cost multiplier. Clear it to fall back to the global price.

Auto updates

For non-container deployments, one update manager checks releases at startup and every 12 hours by default. Stable checks try gh.monlor.com, fastgit.cc, and ghfast.top before GitHub; preview checks use GitHub's Releases feed. Set auto_update_interval_hours to 0 to disable all checks, or use CCLOAD_RELEASE_BASE_URL to force one private mirror for stable metadata and all release asset downloads. Container deployments switch versions with the latest and beta image Tags instead.

OAuth upstream addresses

CODEX_BASE_URL, ANTHROPIC_BASE_URL, XAI_BASE_URL and ANTIGRAVITY_URL default empty and use each provider's official address. When set, matching OAuth channels use only that global address for data requests, model discovery, tests and quota queries, ignoring the channel URL. Authorization and token refresh still use official endpoints; API-key channels are unaffected. Saving a change restarts the process.

Dynamic channel sorting is opt-in. Enable enable_health_score for success-rate scoring, then enable enable_ttfb_score to add relative first-byte scoring. Tune the two penalties independently with success_rate_penalty_weight, health_min_confident_sample, ttfb_penalty_weight, ttfb_max_slow_ratio and ttfb_min_confident_sample.

Security Baseline

The real proxy-service risk is not UI polish; it is exposing upstream keys or the admin surface to the wrong audience.

Pre-production checklist

  • Store the strong password in Secrets, not in the repository.
  • Create at least one API access token; otherwise /v1/* returns 401 by design.
  • Restrict admin-console access on public deployments or place it behind a protected network.
  • Do not use CCLOAD_ALLOW_INSECURE_TLS as a long-term setting.

CCLOAD_PASS=your_strong_admin_password
CCLOAD_API_TOKENS=client_token|production

# Optional: choose exactly one primary database
CCLOAD_MYSQL=user:pass@tcp(host:3306)/ccload?charset=utf8mb4
# CCLOAD_POSTGRES=postgres://user:pass@host:5432/ccload?sslmode=require

# Optional: add a local SQLite read replica
CCLOAD_ENABLE_SQLITE_REPLICA=1
CCLOAD_SQLITE_LOG_DAYS=7

# Optional: bypass broken upstream DNS
