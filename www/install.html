Choose the deployment path first

Docker Deployment

This is the production path with the fewest moving parts. Download the compose file and environment template, set the password, then start the service.

Prepare configuration

Copy the official docker-compose.yml and .env.docker.example, then set a strong CCLOAD_PASS in .env.

Start the service

The default port is 8080; the admin console is under /web/, and API proxy endpoints are under /v1/* and /v1beta/*.

Create access tokens

After logging in as an administrator, create API tokens on the token page. API-token users can also sign in to the Web console for a read-only dashboard scoped to their permitted channels and usage data. Proxy endpoints return 401 when no token exists; that is the secure default.

bash 
curl -o docker-compose.yml https://raw.githubusercontent.com/caidaoli/ccLoad/master/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/caidaoli/ccLoad/master/.env.docker.example

# Required: set the admin console password
nano .env

docker-compose up -d
docker-compose logs -f ccload

Hugging Face Spaces

Spaces work well for quick public deployments. The operational risk is that /tmp is cleared on restart, so long-term usage should use external MySQL or PostgreSQL and optionally enable the SQLite replica for faster reads.

Space settings

  • Create a Space and choose Docker as the SDK.
  • Use ghcr.io/caidaoli/ccload:latest in Dockerfile.
  • Add CCLOAD_PASS in Secrets; do not put it in public files.
  • Create an API access token in the admin console before production access.

Persistence guidance

  • Temporary testing: set only CCLOAD_PASS and use the default SQLite storage.
  • Long-term usage: set exactly one of CCLOAD_MYSQL or CCLOAD_POSTGRES.
  • High-read workloads: also set CCLOAD_ENABLE_SQLITE_REPLICA=1.
  • Control the empty-SQLite log import window with CCLOAD_SQLITE_LOG_DAYS; later hybrid startups import only the log tail. All storage variables are bootstrap-only and stay environment variables.
Dockerfile 
FROM ghcr.io/caidaoli/ccload:latest

ENV PORT=7860
ENV SQLITE_PATH=/tmp/ccload.db
EXPOSE 7860

# Pin a stable release instead of latest:
# FROM ghcr.io/caidaoli/ccload:v4.9.0

Homebrew

Install stable release binaries on macOS/Linux (ARM64 or AMD64), with SHA-256 verification and no Go compiler required.

When editing .env below, add CCLOAD_PASS=your_strong_password with your own strong password. Optional settings such as PORT go in the same file.

bash 
brew tap caidaoli/ccload https://github.com/caidaoli/ccLoad.git
brew install caidaoli/ccload/ccload

mkdir -p "$(brew --prefix)/var/ccload"
cd "$(brew --prefix)/var/ccload"
(umask 077; touch .env)
chmod 600 .env
${EDITOR:-vi} .env

brew services start caidaoli/ccload/ccload

Open http://localhost:8080/web/. Configuration and data remain under $(brew --prefix)/var/ccload, with the default database at data/ccload.db. Service logs are under $(brew --prefix)/var/log/ccload. For foreground use, run ccload from the configuration directory instead of starting the service.

Upgrade or stop the service

bash 
brew update
brew upgrade caidaoli/ccload/ccload
brew services restart caidaoli/ccload/ccload

brew services stop caidaoli/ccload/ccload

Homebrew follows stable releases only and preserves your configuration and data across upgrades. In-app updates are disabled; use brew upgrade to update.

Source Builds and Binary Runtime

Use source builds for development and customization, and binaries when you do not want to maintain a build environment. Both require CCLOAD_PASS before startup.

Source build

Builds must enable the sonic tag. Use make build directly instead of maintaining a forked build script.

bash 
git clone https://github.com/caidaoli/ccLoad.git
cd ccLoad

export CCLOAD_PASS=your_admin_password
make build
./ccload

Binary runtime

Download the ccLoad artifact for your platform from Releases, make it executable and run it. Cursor SDK Bridge is installed automatically when needed; offline archives are available from its official release page.

bash 
wget https://github.com/caidaoli/ccLoad/releases/latest/download/ccload-linux-amd64
chmod +x ccload-linux-amd64

# Cursor SDK Bridge is installed automatically when a Cursor channel exists.
# Offline: place cursor-sdk-bridge beside ccLoad, or set CURSOR_SDK_BRIDGE_BIN.
# Archives: https://github.com/cursor/sdk-bridge/releases

export CCLOAD_PASS=your_admin_password
./ccload-linux-amd64

Post-deployment verification

Verify the process first, then the configuration entry point, then send a real proxy request with a real token. Do not ignore 401 responses; they usually mean tokens have not been configured yet.

bash 
curl -s http://localhost:8080/health
curl -s http://localhost:8080/public/summary

# Admin console
# http://localhost:8080/web/

# API proxy endpoint examples
# POST http://localhost:8080/v1/messages
# POST http://localhost:8080/v1/chat/completions
# POST http://localhost:8080/v1/responses
# POST http://localhost:8080/v1/images/generations
# POST http://localhost:8080/v1beta/models/{model}:generateContent
